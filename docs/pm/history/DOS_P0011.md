# DOS:P11  (2026-06-11)

## Goal

Started as "merge the reverse path" (the DOS:P10 headline carry-over), then pivoted —
at the user's direction, mid-session — into the much bigger dogfooding lesson from
edgenta_OKR: **DeliveryOS had no post-build iteration story.** Small changes and bug
fixes were happening ad-hoc (direct agent instructions + a hand-rolled markdown
defect list), bypassing DeliveryOS entirely. This session built that missing loop.

### 3. All-panels-unstyled CSS bug — found and fixed (`6fa4b70`)

User screenshot showed the Discover panel rendering in raw 1990s HTML. Root cause:
vite attaches the shared Tailwind stylesheet to a `_tailwind-*.js` chunk reached via
`imports`, but `htmlFactory` only linked the entry's *own* `css` (empty) — so **every
panel had been shipping with no stylesheet at all**. Fix: `collectCss()` walks the
manifest import graph. Also enlarged the Raw Idea hero field (`max-w-2xl→3xl`,
min-height `10rem→18rem`). +1 regression test.

`code --install-extension`. Note the **0.1.0 version is ahead of the official tag**
(still `v0.0.2`; `v0.1.0` remains gated on the publication steps).

## Learned / gotchas

- **`/btw` UI feedback mid-build is gold** — the CSS bug had been invisible since the
  webview build landed because nobody compared the styled design to what shipped.
- The user finds the clipboard copy-paste loop (Discovery/PRD/Decompose/CR prompts)
  "very 1990s". The modern replacement already exists in-repo: the EXECUTE-stage
  terminal-handoff machinery (`reverseLauncher`/`resultWatcher` pattern). Pointing it
  at the front stages is a coherent, sizeable roadmap item — discussed, not built.
- New-panel breakage surface (vite multi-entry + serializer) once again contained by
  the worktree pattern; mirroring the CR panel 1:1 worked without advisor escalation.
