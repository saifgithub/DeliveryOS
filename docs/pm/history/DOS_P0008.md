### Change Request (CR) feature — `6f31434`

**Structural gap solved:** PRD edits after requirements decomposition silently orphaned the requirements
catalogue — no propagation path, no warning. This session shipped an explicit Change Request flow:

1. User logs free-text CR description in the new CR panel
2. Extension generates an AI prompt embedding PRD + requirements catalogue + CR description (sentinel-wrapped blocks)
3. User pastes the AI's JSON delta (`{ added, edited, deleted }`)
4. Extension applies mutations (add/edit/delete requirement entries in memory.sqlite)
5. CR entry versioned with `addresses` links → each affected requirement

## Technical gotchas

- **`exactOptionalPropertyTypes: true`** — can't spread `{ optionalField: value | undefined }` into interface literals. Fix: build required fields first, then conditionally assign optional ones via mutable intermediate or cast.
- **Contracts dist staleness** — every edit to `contracts/src/*.ts` needs `npm run build:contracts` before extension workspace sees new exports.
- **Parser `readonly` arrays** — use mutable intermediate `patchFields` object to avoid TS2540 on `EditedRequirement.patch`.
- **Broadcast pattern** — use `this.messenger.sendNotification(RequirementsChanged, BROADCAST, ...)`, not nonexistent `_onRequirementsChanged.fire`.
