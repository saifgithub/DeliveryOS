## Goal

User had 36 requirements for a dogfood project (edgenta_OKR) in DeliveryOS and wanted to fire the MABP build process. They were unsure how to trigger it — this was both a practical execution question and a "learning moment" to codify the process as reusable skills.

## What landed

### New global skills

Two skills created in `~/.claude/skills/` (global, available in any project):

**`sm-mabp-plan`** (SKILL.md + REFERENCE.md)
- MABP Phase A: transforms a DeliveryOS project (PRD.md + `.deliveryos/memory.sqlite`) into a Phase B-ready build workspace.
- Reads requirements from SQLite, groups into chunks, writes chunk specs + READY.md + BUILD_STATUS.md, bootstraps project (git init, CLAUDE.md, .gitignore, session-config.yml).
- Hard constraint: no application code — planning only.

**`sm-mabp-run`** (SKILL.md + REFERENCE.md)
- MABP Phase B architect entry point: pre-fire audit → spawn builder sub-agent → spot-check evidence manifest → spawn QA sub-agent → recommend verdict.
- Usage: `/sm-mabp-run` (next pending), `/sm-mabp-run 3` (specific chunk), `/sm-mabp-run all` (all serially).
- Skill naming convention established this session: all skills MUST be prefixed `sm-` to avoid clashes.
