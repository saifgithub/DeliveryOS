### 2. Parallel-build workflow established

To experiment without touching `main`, set up a long-lived **git worktree**:

```
git worktree add ../DeliveryOS-rpath -b feat/code-to-docs
```

`../DeliveryOS-rpath` is a second working directory on its own branch, sharing the same
`.git`. `main`'s files never change during the experiment; the safety net is three-deep
(origin backup + worktree isolation + a `pre-rpath-merge` tag at merge time). This is the
reusable pattern for any future risky feature: build in a worktree, merge only when green.
Note: `npm install` is required in a fresh worktree (hoisted monorepo `node_modules` are
not shared).

### 3. Reverse path (code → docs) — built, green, NOT merged

The feature that lets DeliveryOS derive a PRD from an existing codebase — the inverse of
its forward `idea → PRD → code` pipeline, and the prerequisite for dogfooding DOS on DOS.

**Ingestion decision (user):** agent handoff (deep read) — DOS writes an analysis brief,
launches Claude Code in the terminal, the agent reads the *whole* repo and writes a PRD
markdown back, DOS watches + parses it. No clipboard size limit.

**Key architectural insight:** the **PRD is the convergence point**. Once a PRD is in the
MemoryStore, the entire existing downstream pipeline (decompose → REQ-NNN → test specs →
briefs) works unchanged. So the reverse path is just *one new front stage*; it reuses
`parsePrdMarkdown()` + `upsertPrdParent()` verbatim.

Mirrors the existing handoff machinery 1:1, all under a new isolated `.deliveryos-reverse/`
dir (so the forward `result.md` watcher never collides):

| New file | Mirrors | Role |
|---|---|---|
| `extension/src/reverse/analysisPromptBuilder.ts` | discovery/prd prompt builders | Brief; output format pinned to `PRD_SECTION_DEFINITIONS` so it can't drift from the parser |
| `extension/src/reverse/reverseWriter.ts` | `HandoffWriter` | Atomic brief write |
| `extension/src/reverse/reverseLauncher.ts` | `terminalLauncher.buildCommand` | Reuses harness profile `command_template` + `shellQuote`, substituting `.deliveryos-reverse/` paths |
| `extension/src/reverse/reverseWatcher.ts` | `ResultWatcher` | Watches `prd.md` (250ms debounce + SHA dedup) |
| `extension/src/reverse/reverseCapture.ts` | — | The convergence: `parsePrdMarkdown` → `upsertPrdParent` |
| `extension/src/commands/openReverse.ts` + `extension.ts` | handoff wiring | `deliveryos.reverse.run`: ensure intent → write brief → launch → capture → "Open PRD editor" |

**Scoping call:** MVP is **command-driven**, no new React webview panel. A new panel is the
single highest build-breakage surface (vite multi-entry, htmlFactory, serializers) — exactly
the risk the worktree exists to avoid. A command fully exercises the agent-handoff loop and
drops the user into the *existing* PRD editor. Panel is a clean fast-follow.
