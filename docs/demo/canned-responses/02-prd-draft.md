# PRD — Bug Triage Assistant

---

## Goals

Build a lightweight bug triage REST API that lets engineering teams submit and retrieve bug reports programmatically. The first iteration focuses on the submission and retrieval flow; AI-powered severity suggestion is a follow-on requirement.

---

## Users

**Primary:** Backend developers and QA engineers integrating bug tracking into CI/CD pipelines or internal dashboards. They interact via REST API calls, not a GUI.

**Secondary:** Engineering managers who query the API to generate triage reports and track open defect counts.

---

## Requirements

1. **REQ-001 — Bug Submission API (High priority):** Provide `POST /bugs` to create a bug report and `GET /bugs/{id}` to retrieve one. Requests must be authenticated with a Bearer token. The API must return HTTP 201 on creation with the new report ID, HTTP 200 on retrieval, HTTP 404 when the ID is unknown, and HTTP 422 on missing required fields.

2. **REQ-002 — List Bugs (Medium priority):** Provide `GET /bugs` to list all bug reports with optional filters for severity and status. Returns a paginated JSON array ordered by creation time descending.

3. **REQ-003 — AI Severity Suggestion (Low priority):** After a bug report is submitted, an AI model analyses the title and description and returns a suggested severity (`low`, `medium`, `high`, `critical`) with a confidence score. The suggestion is advisory and does not override the reporter's chosen severity.

---

## Non-Goals

- A user-facing web interface (the frontend placeholder exists but is out of scope).
- User account management or signup flows.
- Email or webhook notifications.
- Database persistence beyond the in-memory repository stub (that is a future infrastructure concern).

---

## Success Metrics

- All four integration tests for REQ-001 pass (`pytest -q` reports 4 passed, 0 failed).
- Zero ruff lint errors on `ruff check .`.
- `POST /bugs` responds in under 200 ms on a development machine.
- The API contract matches the OpenAPI schema generated by FastAPI.

---

## Open Questions

- Should severity be an enum validated by Pydantic or free-form text? (Decision: Pydantic enum with values `low | medium | high | critical`; default `medium`.)
- Does `GET /bugs/{id}` require authentication? (Decision: yes, consistent with `users.py` pattern — all routes require Bearer token.)
